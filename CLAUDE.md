# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Next.js dev server (Turbopack) on http://localhost:3000
- `npm run build` — production build; also runs type checking. Fails without `DATABASE_URL` set (see below).
- `npm run lint` — ESLint (flat config in `eslint.config.mjs`)
- `npx tsc --noEmit` — typecheck on its own. If `LayoutProps` is reported missing, run `npx next typegen` first; it's a global generated by Next.
- No test runner is configured yet. There is no way to run a single test.
- Database (Drizzle + Neon Postgres):
  - `npm run db:generate` — create SQL migrations from schema changes in `src/lib/db/schema`
  - `npm run db:migrate` — apply migrations
  - `npm run db:push` — push schema directly (no migration files)
  - `npm run db:studio` — Drizzle Studio
- `npm run auth:generate` — regenerates Better Auth's tables (`user`, `session`, `account`, `verification`) into `src/lib/db/schema/auth.ts`. Run this after changing the Better Auth config, then apply with the db scripts.

## Environment

Copy `.env.example` to `.env.local`. Required: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `NEXT_PUBLIC_APP_URL`.

Env loading is split between two paths:
- Next.js loads `.env.local` automatically for app code.
- `drizzle.config.ts` loads `.env.local` explicitly via `dotenv`, because drizzle-kit runs outside Next.

## Architecture

The app is the App Router with `src/` and the `@/*` alias. The pieces that span multiple files:

- **DB client** — `src/lib/db/index.ts` creates a Drizzle instance over Neon's HTTP driver (`drizzle-orm/neon-http`) and throws at import time if `DATABASE_URL` is missing. Anything that imports `@/lib/db` therefore needs the env var, including build-time route collection.
- **Schema** — all tables live in `src/lib/db/schema/`, and `schema/index.ts` is the barrel that Drizzle and the DB client read. New table modules must be re-exported from there to be picked up. Drizzle config points at this directory.
- **Auth** — `src/lib/auth.ts` is the server-side Better Auth instance, using the Drizzle adapter with the same `schema` barrel. The HTTP handler is the catch-all route `src/app/api/auth/[...all]/route.ts`, which wraps `auth` with `toNextJsHandler`. The browser client is `src/lib/auth-client.ts`. The auth flows (sign-in, sign-up, sessions) are not built yet; the config has no auth methods enabled.
- **Schema/auth dependency** — the Better Auth adapter needs its tables to exist. Until `auth:generate` plus a db push/migrate has run, the build logs "Missing tables" and runtime auth calls will fail. That warning is expected at this stage.
- **Next.js config** — `next.config.ts` enables `cacheComponents` and `partialPrefetching`, and adds a Tailwind Turbopack loader for `*.css`. These affect how pages and data fetching are written, so check the Next docs before changing them.
